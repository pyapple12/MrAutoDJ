# 审计报告归档与任务清单生成（audit-report）

audit-project 审计完成后的**归档流程**。只写文档，不修改业务代码。

`z.plan.md`（审计附录与豁免定案）与 `x.progress.md`（任务清单）是本项目的工作文档：尚不存在时首次归档创建，不与调研报告（w.study.md）混用。

## 编号规则（MR 2026-11-05 定稿；对齐 CapsulePulse A/FIX 同号绑定）

### 审计报告编号（z.plan.md 附录）

- 格式：`## 附录 A{NNN}：全量代码审计报告（第N轮，YYYY-MM-DD）`
- 编号：`A` 开头 + 三位数字，与修复组 `FIX{NNN}` **恒同号**（见下）
- 取号：**随 FIX 号**（A 侧不独立取号）——先按下方规则定出 `FIX{NNN}`，A 号即同一数字；写入前核对 z.plan.md 中 `## 附录 A\d{3}` 无同名占用
- **历史对应关系不变**：既有附录 A001/A002/A003 分别对应 x.progress.md 的 G/H/I 字母系列（三线轨道启用前的历史实践），新审计自下一可用 A/FIX 号起，不回改历史

### 修复任务清单编号（x.progress.md）

- 任务组格式：`### FIX{NNN}: 第{N}轮审计修复 [audit#A{NNN}]`，追加在 x.progress.md 任务区末尾（从上到下 = 从旧到新）
- 子任务格式：`- [ ] FIX{NNN}.{序号} [P{级别}] {标题} —— {做法}；验证：{检验方式}`
- P 级不入编号：条目内以 `[P0]`/`[P1]`/`[P2]`/`[P3]` 标注，按严重度排序平铺
- **A/FIX 同号绑定**：审计附录 `A{NNN}` 与修复组 `FIX{NNN}` **恒同号**；取号 = 搜索 x.progress.md 中 `^### FIX\d{3}` 的**最大值** +1（无历史时 FIX001），**A 侧不独立取号**；轮次叙述（"第 N 轮"）与编号解耦——FIX 号被非审计批（PATCH / 功能批等）占用时，审计顺延取号防撞号

## 执行流程

### Step 1：询问环节（编号确认，必做）

向用户确认以下编号规则（展示默认值，用户可改）：

1. **审计 / 修复编号（同号绑定）**：默认 `A{下一可用 FIX 号}`，即 `FIX{同一号}`（如 A004 / FIX004）——确认或指定（A 侧不独立取号）
2. **是否补编号**：历史无编号报告是否补
3. **观察项复核**：逐条念本轮观察项，问"是否有要提升为 P 级的？"提升的 → 加入修复清单（含 P 级编号）随任务组写入

用户确认后按确认值执行；用户指定其他规则时以用户为准并**在本文件记录该次例外**。

### Step 2：写入 z.plan.md 附录

- 在 z.plan.md 末尾追加 `## 附录 A{NNN}：全量代码审计报告（第N轮，YYYY-MM-DD）`（既有附录按编号升序排列，新附录置于文末）
- **内容结构（与 audit-project 报告格式同步，四节）**：
  - 头部：范围/方式/状态（📌 待修复，任务组见 x.progress.md）
  - 零、上轮修复复核清单（✅仍在/⚠️回退/❌回归 + 证据）
  - 一、P0-P3 修复清单（文件:行号/类型/描述/建议/性质[新增|遗留]/影响面）
  - 二、参考级观察项（含回落理由）
  - 三、亮点（可省略）
- 影响面取值：音频引擎 / 分析管线 / 转场编排 / 曲库与缓存 / UI 控件 / 主窗口 / 配置体系 / 通用工具 / 跨模块 / 文档
- 状态行：`> 状态：📌 待修复（FIX{NNN} 任务清单见 x.progress.md）`；修复完成后回改为 ✅ 并注明验证结论

### Step 3：生成任务清单写入 x.progress.md

- 追加任务组 `### FIX{NNN}: 第{N}轮审计修复 [audit#A{NNN}]`
- 条目按 P 级排序平铺：`[P0] 正确性/安全` → `[P1] 防御/错误策略` → `[P2] 配置化/重复` → `[P3] 清理/规范`，末尾加验证收尾条目（全量探针回归 + 冒烟 + 截图核对节点）
- 每条格式：`- [ ] FIX{NNN}.{序号} [P{级别}] {标题} —— {做法}；验证：{检验方式}`
- **必须含文件/函数级修复方案**（`—— 做法` 指明改哪个文件哪一行、改成什么）；验证方式可执行（probe 脚本名与断言项 / 冒烟 import / 截图读图核对）

### Step 4：汇报

- 报告归档位置与编号、清单位置与 FIX 任务组号
- 询问用户：是否按 P0 开始修复

## 硬性约束

- 只写 z.plan.md 与 x.progress.md（及用户指定的文档），不修改业务代码
- 编号必须先询问确认（用户是编号的最终决定者）
- 编号递增按"最大值+1"，不允许跳号或重复
- 报告内容来自审计结果，不自行增删问题条目
